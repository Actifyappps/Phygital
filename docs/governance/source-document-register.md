# Phygital source-document register

**Purpose:** a navigable register of the governing and supporting Phygital records that inform this repository. It is deliberately broader than the digital specification series so that technical work does not lose the commercial, physical, regulatory, operational, evidence or pilot context.

**Rule:** the register records source authority and status; it does not make a draft approved, close evidence, or replace the canonical Notion page. Where a document has multiple copies, use the canonical page linked below and retain superseded versions only as historical records.

## Repository maintenance
When a canonical source changes:
1. Fetch the new version and verify status, version, parent and completeness.
2. Compare requirements and decisions against current repository documents.
3. Record additions, removals, conflicts and impact.
4. Update traceability, ADRs, domain/data/API/UI/security/test/operations artefacts as applicable.
5. Preserve previous implementation and evidence history; rerun affected tests.
6. Do not mark a programme gate closed based solely on repository changes.
