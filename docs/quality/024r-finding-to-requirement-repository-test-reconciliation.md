## 1. Purpose and interpretation

This record connects each 024-R finding to its governing requirement, repository design home, verification obligations and remaining decision/ownership gate. It supplements the existing audit coverage matrix and correction implementation record; it does not replace the Notion source specifications.

Status terms are deliberately separate:
- **Source corrected:** a source specification was amended and the correction is recorded.
- **Represented:** a repository design home or crosswalk exists.
- **Specified:** the requirement is sufficiently detailed in an approved or reviewed specification.
- **Implemented:** reviewed code/configuration exists in an approved architecture.
- **Executed:** the relevant test actually ran and raw evidence is retained.
- **Accepted/closed:** the authorised reviewer accepted the evidence and residual risks.

A finding can be represented without being specified, implemented, executed or accepted.

## 3. Cross-finding acceptance rules

1. Every requirement must retain its source ID and controlling authority. This record does not create replacement requirement IDs.
2. Map detailed cases to the canonical 024-G QAT catalogue, 024-F security controls and 014 technical harness where applicable. Do not create duplicate test IDs or claim coverage from a name-only cross-reference.
3. Test both positive and negative paths for P0/high-risk controls. A planned test is not an executed test.
4. Record build/commit, environment, configuration, synthetic fixture version, exact procedure, expected and actual result, raw evidence, defects, retest and reviewer.
5. Distinguish UI, API, database/RLS, integration, operational and independent-assurance evidence.
6. A specification correction is not implementation; implementation is not execution; execution is not independent acceptance.
7. Any source conflict blocks affected acceptance until the authority and disposition are recorded.
